## S1：FA 小批选核（`ggml/src/ggml-cuda/fattn.cu`，Volta 分支）

```cpp
if (volta_mma_available(cc) && Q->ne[0] != 40 && Q->ne[0] != 72) {
    // env: GGML_CUDA_FA_SMALL_BATCH_VEC
    static const bool small_batch_vec = getenv("GGML_CUDA_FA_SMALL_BATCH_VEC") != nullptr;
    const int vec_limit = small_batch_vec ? 16 : 2;
    if (can_use_vector_kernel && Q->ne[1] * gqa_ratio_eff <= vec_limit) {
        return BEST_FATTN_KERNEL_VEC;
    }
    if (Q->ne[1] * gqa_ratio_eff <= 16) {
        return BEST_FATTN_KERNEL_TILE;
    }
    return BEST_FATTN_KERNEL_MMA_F16;
}
```

- 上游行为：`vec_limit = 2` → decode(n_q=1) 走 VEC，verify(n_q=2~4，本模型 gqa_eff=2) 走 TILE → 两条路数值不同
- 修复（开关开）：`vec_limit = 16` → n_q=1~8 全走 VEC → verify 与 decode 同核
- 附带影响：≤8 token 的极短 prompt（prefill）选核会从 TILE 变 VEC；正常长度 prompt 不受影响
- 注意：decode(n_q=1) 的选核与 VEC 核数值本身不变（上游也是 VEC）

## S2：GDN vec4 布局（`ggml/src/ggml-cuda/gated_delta_net.cu`）

```cpp
// 上游 A2 引入的分支：vec4 = n_tokens > 1
static const int vec4_env = []() { ... getenv("GGML_CUDA_GDN_VEC4") ... }();
const bool vec4 = vec4_env >= 0 ? vec4_env != 0 : n_tokens > 1;
```

- 背景：A2 优化给 GDN 加了 vec4 布局（`use_vec4 = VEC4 && rows_per_lane == 4 && warp_size == 32 && !KDA`），只用于 `n_tokens > 1`（prefill）；单 token decode 走原标量路径
- 两套布局的 lane→行映射不同（4*lane+r vs r*32+lane）→ warp 归约顺序不同 → 末位数值不同
- 修复（`GGML_CUDA_GDN_VEC4=1`）：一律 vec4 → decode 与 prefill/verify 同布局
- 代价：约 -0.5~0.8%（d0 -0.8%、d32768 -0.5%，全部来自这一条）；反过来让 prefill 退标量会丢掉 A2 的 prefill 收益（T19 pp +8.7~35.6% 主要来自这里），所以选"decode 迁就 prefill"

```cpp
if (pb_force > 0) {

} else if (Q->ne[1] <= 8) {

} else {
    // prefill 保持上游的波次搜索
    ...
}
```

- 上游行为：pb 由"波次效率搜索"决定，随 padded KV 长度变化（跨 256 边界就变）→ decode 在不同位置用不同 pb；verify 一次只算一个 pb → 对不齐
- 修复：n_q≤8（decode + verify）钉成与位置/批型无关的常量；空块贡献严格为 0，所以不影响正确性
- 实测：不修时 verify 与 decode 的 logits 首个差异在 position 255（首个 256 边界）

## 调试开关汇总（默认全关）

| 环境变量 | 位置 | 作用 |
|---|---|---|
| `GGML_CUDA_FA_SMALL_BATCH_VEC` | `fattn.cu` | 置 1 = 小批强制 VEC 核（S1 修复开关） |
| `GGML_CUDA_GDN_VEC4` | `gated_delta_net.cu` | `=0` 强制标量布局 / `=1` 强制 vec4（S2 开关） |
| `GGML_CUDA_FATTN_PB_FORCE` | `fattn-common.cuh` | 非 0 = 强制 KV 切分数（研究 pb / 复现 PB=1 等） |
| `GGML_CUDA_FA_FORCE` | `fattn.cu` | 强制 FA kernel 类型（VEC/TILE/MMA） |
| `GGML_DBG_LOGITS` | `common/sampling.cpp` | 采样点 logits dump 到文件（对齐两条路径用） |

（开关默认关闭时行为与 T19 一致；S3' 是内建的，无开关，需要时用 `GGML_CUDA_FATTN_PB_FORCE` 覆盖。）

## 验收与代价（当时结论）

- 验收：修复全开时，n-max 1/2/3 与不开 spec 在 短 900 token、32k 150 token、128k 100 token 上**逐 token 一致**
- 代价：约 -0.5~0.8%（全来自 S2）；PPL 4.3562（对照 4.3572，不变）
- 附带发现：PB=1 全局禁用 KV 切分 = -31%（不可用方案，已废弃）

## 为什么和"原版 no-MTP"对不上（关键）

本 fork 的 prefill 优化（GDN vec4 的 prefill、T12/T16 的 FA 切分）本身已经改变了末位数值 → 即使 decode 完全保持原版路径，输出照样与原版分叉（证据：T19 生产版 greedy d0@207 分叉）。
想"逐位等于原版"只有一条路：干净上游 + 极小补丁（`vec_limit` + `pb` 两处，且 pb 会引入新的取舍，见 README 第四节）。
