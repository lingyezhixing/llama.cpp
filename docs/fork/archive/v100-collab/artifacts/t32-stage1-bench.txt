===== 汇总 =====
chunk | chunks | write s | write MiB/s | write ms/chunk | read s | read MiB/s | read ms/chunk
512   | 63     | 1.28    | 1198.1      | 20.30          | 0.81   | 1896.4     | 12.82
1024  | 32     | 1.11    | 1377.8      | 34.75          | 0.74   | 2062.5     | 23.21
2048  | 16     | 0.96    | 1594.1      | 60.06          | 0.66   | 2308.8     | 41.47

- ms/chunk 翻倍比: 写 20.30 -> 34.75 -> 60.06 (x1.71, x1.73); 读 12.82 -> 23.21 -> 41.47 (x1.81, x1.79)
- 固定开销份额 (由翻倍比推): 写 ~29%, 读 ~19% (chunk 512); 传输字节仍占主导
- 对照阶段 0 全量 state 带宽 (27B Q6_K f16 V): H2D 2.37 GiB/s = 2426.9 MiB/s / D2H 2.60 GiB/s = 2662.4 MiB/s
  - range 读: 512 时达全量 H2D 的 78%, 2048 时达 95% -> 逐 cell 分配有开销但有限
  - range 写: 512 时仅为全量 D2H 的 45%, 2048 时 60% (写计时含每 chunk 新 vector 分配/first-touch, 口径保守)

===== 尺寸换算 (目标 q8_0, range API 仅 attention, 不含 recurrent 常数) =====
- 32K 区间 payload 1532.0 MiB = 1606418432 B; 63 个 8B 头 -> 50200 B/token (49.0 KiB/token)
- chunk 512 -> 24.51 MiB (25.70 MB) per 块 (8B 头含)
- 100K KV = 5.020 GB = 4.675 GiB; 按全量带宽外推 H2D ~1.97 s / D2H ~1.80 s (仅 attention target)
- 说明: range payload = io header 8B + 仅 attention KV (hybrid 转发给 mem_attn, 见 2.2.6);
  recurrent 常数为单独锚点项 (162 MiB), 不在此 payload 内

===== 判读与决定 =====
- ms/chunk 随 chunk 近似翻倍 (每翻倍 x1.71-1.81, 非持平) -> 固定开销不足以改变结论;
  512 保住最好复用粒度 (块内分叉 <=512 token), 维持 `--tree-chunk` 默认 512
- 上调到 2048 仅省 100K 序列约 1.4 s 搬运 (写 4.0->3.0 s, 读 2.5->2.1 s), 代价是分叉重复翻 4 倍
- 无需强制批量装载路径; 写侧 45% 带宽有优化空间 (候选: 复用 blob 缓冲/合并 cell 拷贝), 记入阶段 2 观察,
  不影响设计 (写判定不受阻)
