2) Crash found and fixed in this round
   Repro: hybrid model without rollback snapshots (0.8B-MTP, no --spec-type => n_rs_seq=0, seq_rm_type=FULL).
   A tree restore covering the whole prompt (C == task.n_tokens) made the server decrement n_past (TAG_PROMPT_LOGITS)
   and call seq_rm(pos_next(), -1); the recurrent memory cannot roll back a state restored via set_partial without
   snapshots -> 'failed to remove sequence N with p0=.., p1=-1' -> abort. Reproduced with text-only prompts too.
   Root cause chain: (a) the reuse logic requires a checkpoint below the reuse point for hybrid memory;
   (b) media prompts had no rebuilt checkpoints, so a full-prompt restore fell into do_reset or, after the skip,
   into the 1-token rollback; (c) rollback is only possible when the context reports PART/RS.
   Fix: tree restore takes leave_one (cap the restore point at min(deep, tokens.size()-1)) whenever the
   target or draft context cannot roll back; the checkpoint search is skipped when the tree restored at exactly
   n_past (tree_restore_point); media checkpoints are rebuilt (with a.tok / a.pos units) so a rollback-capable
   model keeps the deep reuse; the leave_one cap never exceeds the verified prefix (review finding, tested by mutation).
   Review: delta d9a62d8ef+1bfb1b38a reviewed; 1 Critical + 1 Important + 1 Minor found and fixed; scoped re-review: all addressed.
