# T04: ub 与服务端配置固化

状态: PROPOSED (用户归调参类, 放最后)
优先级: P2
预期收益: +16-23% (已实测), 零代码

## 背景数据 (报告 2.2)

| ub | 优化后 t/s |
|---:|---:|
| 512 | 934 |
| 1024 | 1090 |
| 2048 | 1152 |

- 反量化固定开销约 120ms/ubatch, ub 越大摊得越薄
- 服务端 8k prompt: 无 MTP 861 t/s vs 含 MTP 800 t/s (prefill 阶段 MTP 拖后腿 -7%)
- `-ctk q8_0` 在 184k 上下文省约 2.8GB 显存, 质量影响小

## 任务

1. 验证 ub1024 / ub2048 在 32k 上下文下不 OOM (22GB 权重 + KV + activation)
2. 确定默认配置: 建议 ub2048 + `-ctv q8_0` (+ `-ctk q8_0` 视上下文), 并给出 32k/64k 两种上下文下的可行组合
3. 服务端: prompt 处理阶段关闭 MTP (或确认 MTP 对 prefill 的影响可否规避), 生成阶段再开 (与 T06 联调)
4. 把最终配置写进 STATUS.md 的"当前最快配置"

## 验收

- pp512 >= 1150, pp4096 >= 1100, 32k 上下文稳定不 OOM
- 配置有明确命令, 可一键复现
