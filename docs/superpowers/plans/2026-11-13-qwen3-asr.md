# Qwen3-ASR Complete Support Implementation Plan

> **For agentic workers:** Follow the repository `AGENTS.md` and the task order below. Steps use checkbox (`- [ ]`) syntax for tracking. This plan follows the private-fork `AGENTS.md`; upstream contribution rules do not apply.
>
> **Plan revision 2026-11-13:** Reconciled with the current tree. The main changes: aligner detection now follows the real HF config (`Qwen3ASRForConditionalGeneration` + `thinker_config`); engine creation/teardown uses `load_model()`/`destroy()`; route registration uses `server_register_routes()` and `ctx_http.del`; the new realtime API is explicitly separate from the existing `/v1/realtime`; `n_ctx` means per-sequence context (`n_ctx_slot()`); new C++ tests must be verified on the current shared build.

**Goal:** Add the two independent Qwen3-ASR APIs from the design: async offline transcription with optional fine-grained timestamps, and append-only realtime transcription with bounded context and realtime priority.

**Architecture:** Build a new `server_asr` subsystem beside the existing chat/audio endpoints. It owns a dedicated ASR llama context, borrows the server ASR `mtmd_context`, optionally owns a Qwen3VL classifier aligner, and serializes offline and realtime work through one mutex. Offline jobs run on one worker thread; realtime runs on the WebSocket thread and preempts offline jobs at bounded safe points.

**Tech Stack:** C++17, llama.cpp server, mtmd, cpp-httplib, miniaudio, CUDA/CPU, Python pytest integration tests.

**Spec:** `docs/superpowers/specs/2026-11-13-qwen3-asr-design.md`

## Global Constraints

- Committing and pushing are allowed in this private fork under `AGENTS.md`. The report steps below mean: summarize the result, commit the completed task with a concise message, and push only to this fork when the task calls for it. Do not push to upstream or create upstream PRs.
- Keep all new code and code comments ASCII only. No em dash, Unicode arrows, or Unicode ellipsis.
- Do not reuse code from the abandoned Qwen3-ASR branch.
- Existing `/v1/audio/transcriptions`, `/v1/realtime`, chat, and completion behavior must not change.
- One realtime session at a time. One offline job running at a time.
- Realtime has priority. Offline jobs pause and resume automatically.
- Offline and realtime work use one `asr_mutex`; only one uses the ASR context at a time.
- Offline API is asynchronous. `POST` returns `202`, `GET` polls, `DELETE` cancels or removes.
- Offline timestamps use only `items`, in milliseconds, finest granularity. No `segments`.
- Realtime text is append-only. Never retract or rewrite emitted text.
- No repetition cleanup in v1.
- Audio formats are WAV, MP3, and FLAC only.
- `context` is capped at 1024 tokens.
- The aligner classifier must use the per-token embedding output path, not vocabulary-wide logits.
- The aligner context defaults to 8192 tokens.
- All wall-clock fields are RFC3339 UTC strings. All durations are integer milliseconds with `_ms` suffix.
- On Windows shared builds, register new C++ server tests outside the `tests/CMakeLists.txt` shared-library guard, but verify the link first: the current build is `BUILD_SHARED_LIBS=ON` and the existing `test-chat`/`test-server-component` targets are guarded. If a test cannot resolve `server-context` symbols, link `llama-server-impl` or build a static test configuration; do not silently skip the test.
- Use the existing build directory and the repo's configured MSVC/CUDA environment. Do not reconfigure CUDA architectures unless required.
- You may execute implementation tasks continuously. Commit completed tasks; push to this fork when the task calls for it. Do not push to upstream or create upstream PRs.

## Codebase baseline (verified 2026-11-13)

These already exist in the tree. Reuse them; do not re-implement them.

- `Qwen3ASRTextModel` and `Qwen3ASRMmprojModel` already convert `Qwen3ASRForConditionalGeneration`; the ASR mmproj already produces `clip.audio.projector_type = qwen3a` with 128 mel bins (`conversion/qwen3vl.py`).
- `qwen3a` audio already encodes 100 mel frames per 13 tokens in 8 second windows (`tools/mtmd/models/qwen3a.cpp`, `tools/mtmd/mtmd-audio.cpp`).
- `mtmd_tokenize` already emits one audio chunk per 8 second qwen3a window (`tools/mtmd/mtmd.cpp`), so the offline/realtime loops can check pause/cancel between chunks.
- `llama_batch_ext`, `llama_process`, `llama_batch_ext_set_output_embd`, `llama_get_embeddings_ith`, `llama_model_n_cls_out`, and `n_embd_out_impl` exist (`include/llama.h`, `src/llama-context.cpp`).
- `src/models/qwen3vl.cpp` already creates the optional `cls_out` tensor and sets `res->t_embd`. Qwen3.5 already shows the classifier-output pattern to copy (`src/models/qwen35.cpp`).
- `server_context_meta`, `mtmd_cap`, `server_register_routes()`, the router proxy wiring, and the sleep/reload path already exist (`tools/server/server.cpp`, `tools/server/server-context.cpp`).
- `/v1/realtime` already implements realtime transcription for streaming-audio models (`mtmd_support_audio_stream`: Voxtral RT, LFM3-A, Gemma4-A). It does not support `qwen3a`; the new `/v1/asr/realtime` is a separate protocol and must not reuse `SERVER_TASK_TYPE_TRANSCRIBE_RT`.
- cpp-httplib already has `HandlerWithContentReader`, and its default payload limit is 100 MiB (`vendor/cpp-httplib/httplib.h`). The default server `post` handler still buffers multipart bodies in memory (`tools/server/server-http.cpp`), so Task 2 is still required.

## Review Focus

- A multi-GB offline upload must stream to disk. It must not be buffered in RAM or fail at cpp-httplib's default 100 MiB payload limit.
- Long offline audio must never silently truncate. It must chunk, report progress, and fail explicitly if a chunk cannot fit.
- Realtime output must never be retracted. Joined `transcript.delta` text must equal the final committed transcript.
- Realtime context resets must not lose or duplicate words at silence anchors or forced low-energy cuts.
- The 5000-class aligner output must use the per-token embedding path. Using vocabulary-wide logits would corrupt output indexing and allocate gigabytes.

- Job manager pause callback returns `realtime_active()`.
- Realtime start:

  2. Wait for `asr_mutex`.

- Realtime end:
  1. Release `asr_mutex`.
  2. Set `realtime_active = false`.
  3. Notify the job manager.

The priority flag arbitrates ASR offline vs ASR realtime only. It does not preempt chat/vision work that holds the shared `mtmd_context::compute_mutex`; realtime start can still wait for one in-flight mtmd encode.
